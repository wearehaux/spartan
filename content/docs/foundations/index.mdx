title: Foundations
description: How the Spartan design tokens are organized and generated.
---

Spartan tokens are authored in Git in `tokens/source.json`. The source began with 547 verified Figma variables; the shared theme contract now contains 766 definitions while retaining the existing keys and identities. A build generates one stylesheet, `tokens.css`, from the authored source. The stylesheet is never edited by hand, and a build does not re-import Figma. See [Theme ownership](/docs/theming/contract) for Brand/System separation and family recipes.

```text
Git-authored tokens/source.json  ->  public/tokens.css
Figma export  ->  separate review candidate  ->  reviewed edits to the authored source
```

## Seven collections

| Figma collection | Modes | CSS prefix |
| --- | --- | --- |
| 01 Primitives | Value | `--sp-prim-` |
| 02 Primary | Blue, Purple, Orange, Sky | `--sp-hue-` |
| 03 Semantic Color | Light, Dark, Light High Contrast, Dark High Contrast | `--sp-` |
| 04 Semantic Foundation | Value | `--sp-` |
| 05 Component | Value | `--sp-` |
| 06 Density | Relaxed, Compact | `--sp-` |
| 07 Style | Atlas, Selene, Helios, Ares | `--sp-` |

A variable named `button/height/base` in 05 Component becomes the property `--sp-button-height-base`.

## Use semantic tokens

Components and your own styles should use semantic and component tokens, not primitives. Semantic tokens change with the active mode; primitives do not.

```css
.card {
  background: var(--sp-color-surface-elevated);
  color: var(--sp-color-foreground-default);
  border: var(--sp-border-width-default) solid var(--sp-color-border-default);
  border-radius: var(--sp-radius-surface);
  padding: var(--sp-space-surface-padding);
}
```

## Regenerate

```sh
pnpm tokens:build   # authored source.json -> public/tokens.css
pnpm tokens:check   # validates the source and fails if generated CSS is stale
```

Figma reconciliation is explicit: `pnpm tokens:drift [export-path]` reports differences without changing files, and `pnpm tokens:import [export-path] [--out candidate-path]` writes a separate review candidate. Review and manually merge accepted changes into the authored source, then regenerate CSS. These commands preserve code ownership; Figma differences do not block code validation.

The pages that follow show live values. They read the current CSS variables, so toggle Light and Dark in the header to see them change.
